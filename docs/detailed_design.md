# Gematria CipherLab — 詳細設計書

## 1. 目的

Gematria CipherLabは、複数の文字数値対応について、入力の正規化、トークン化、数値割当、合計を追跡できる学習用ツールです。計算と歴史的・宗教的な解釈を分け、方式ごとの差と入力処理を明示します。同じ文字体系の方式横断比較と版付き出力も提供しますが、合計の一致や近さを意味として採点しません。

## 2. 構成

- `gematria-core.js`: DOMに依存しない方式定義と計算関数
- `messages.js`: 日本語・英語の画面文言
- `script.js`: タブ、入力、描画、言語切替、モーダル
- `index.html`: セマンティックな画面構造とCSP
- `style.css`: 320px幅を起点とするレスポンシブスタイル

計算コアはブラウザーでは`window.GematriaCore`、Node.jsではCommonJSモジュールとして公開します。テストはブラウザーDOMなしで同じコアを呼び出します。

## 3. 方式定義

| ID | トークンと値 | 置換・除外 |
|---|---|---|
| `simple-english-0` | A=0〜Z=25 | なし |
| `simple-english` | A=1〜Z=26 | なし |
| `english-gematria` | A=6〜Z=156（A=1方式の6倍） | なし |
| `simple-latin23` | `ABCDEFGHIKLMNOPQRSTVXYZ`を1〜23 | J→I、U→V、Wを除外 |
| `agrippa-23` | A〜I=1〜9、K〜S=10〜90、T/V/X/Y/Z=100〜500 | J→I、U→V、Wを除外 |
| `agrippa-27` | Agrippa 23の基礎にU=200、J=600、V=700、HI=800、HV=900を配置 | W→HV |
| `hebrew-gematria` | 22文字の標準値1〜400 | 語末形は通常形と同値 |
| `hebrew-final-values` | 通常形1〜400、語末形ך・ם・ן・ף・ץは500〜900 | 母音・朗誦記号は無視 |

Agrippa 27枠は、Agrippaの表にある追加4項目を現代綴りで入力するための本ツールの転写設計です。原綴りのI/Vが母音か子音かを推測しません。HI/HVは最長一致で認識し、空白や句読点を越えて結合しません。

Hebrew Standardは、ך・ם・ן・ף・ץを通常形と同じ20・40・50・80・90で扱います。Hebrew Final Valuesは別方式として、5つの語末形だけを500・600・700・800・900で扱います。通常形とUnicode正規化の処理は両方式で共通です。方式名は計算規則を区別するためのもので、一方を標準の上位版として扱いません。

## 4. 入力処理

最大入力長は10,000 UTF-16コード単位です。超過時は計算せず、画面へ確認事項を表示します。

### 4.1 英語・ラテン文字

1. NFKCで正規化する。
2. 大文字へ変換する。
3. 方式固有の置換を先に適用する。
4. Agrippa 27枠ではHI/HVを最長一致で調べる。
5. 表にあるトークンを計算対象、空白・句読点・記号・数字を無視、それ以外を除外とする。

### 4.2 ヘブライ文字

1. NFKDで正規化し、表示形を基底文字と結合記号へ分解する。
2. U+0591〜U+05BD、U+05BF、U+05C1〜U+05C2、U+05C4〜U+05C5、U+05C7を母音・朗誦記号として無視する。
3. 表にある文字を計算対象、区切りを無視、それ以外を除外とする。

無視した記号は警告にせず、トレースの注記へ表示します。方式にない文字は除外として警告します。

## 5. 戻り値

`GematriaCore.analyze(input, schemeId)`は、次の情報を再帰的に凍結して返します。

- `schemeId`、`schemeVersion`
- 原入力`input`とUnicode処理後の`normalizedInput`
- 正規化の有無`normalizationChanged`
- 計算対象`tokens`
- 無視した入力`ignored`
- 方式にない文字`excluded`
- 合計`total`

各計算対象トークンは、元の表記、計算用トークン、値、位置、置換の有無を持ちます。

`GematriaCore.getComparableSchemeIds(schemeId)`は、選択方式と同じ`family`を持つ方式IDだけを定義順で返します。異なる文字体系を同じ比較へ混ぜません。

`GematriaCore.createAnalysisPackage(input, selectedSchemeId, comparisonSchemeIds?)`は、選択方式の完全な分析結果と、比較方式の方式ID、方式版、合計、基準との差、計算対象数、除外数、無視数を返します。出力形式は`gematria-cipherlab.analysis`、`formatVersion`は1です。比較方式を省略した場合は同じ文字体系の全方式を使います。異なる`family`の方式指定は拒否します。生成時刻を含めず、同じ入力と方式から同じJSONを生成できるようにします。

## 6. 状態と表示

| 状態 | 処理 | 表示 |
|---|---|---|
| Included | 合計へ加える | 緑系 |
| Normalized | 置換後の値を合計へ加える | 黄系、元→置換後 |
| Excluded | 合計へ加えず警告する | 赤系、取消線 |
| Ignored | 合計へ加えず注記する | 灰色系、破線 |

言語切替時は保存済みの分析パッケージを再描画し、入力と比較を再計算しません。これにより、言語だけを変えたときに計算状態が変化することを防ぎます。

比較カードは選択方式を基準とし、`deltaFromSelected`を符号付きで表示します。値が同じ場合も、意味的関係や信頼度を付与しません。

コピーは表示言語の人間向け要約です。JSONはローカライズしない方式IDと版を正として、選択方式のトレースと比較要約を保存します。どちらもブラウザー内で生成します。

## 7. 不変性

方式定義、マッピング、トークン配列、計算結果を`Object.freeze()`で再帰的に凍結します。複合トークンを並べ替える場合はコピーを作り、定義配列を破壊しません。

## 8. セキュリティ

- ユーザー入力をHTML文字列として解釈しない。
- 描画は`textContent`、`append()`、`replaceChildren()`を使う。
- 外部スクリプト、外部スタイル、外部APIを使わない。
- CSPでスクリプト・スタイル・画像・フォントを同一オリジンへ限定し、接続、メディア、オブジェクト、ワーカー、フォーム送信を禁止する。
- `localStorage`は言語コード`ja`または`en`だけを保存し、例外時も動作を継続する。
- コピー文字列はテキストとして生成し、JSONは`JSON.stringify()`したBlobとして保存する。入力からHTMLやファイル名を組み立てない。

GitHub Pagesでは任意のHTTPレスポンスヘッダーを設定できないため、`X-Frame-Options`は設定しません。`frame-ancestors`はHTMLのCSPメタ要素で無効なので記載しません。

## 9. テスト

`npm test`はNode.js標準のテストランナーを使い、依存パッケージなしで次を確認します。

- 8方式の代表値と表の端点
- Agrippa 27枠の27項目、最長一致、区切り、W→HV
- Hebrew Standardの既知例、語末形、母音記号、表示形
- Hebrew Final Valuesの語末形500〜900とStandardとの差
- 同一文字体系だけの比較、差分、方式ID・版・完全トレースを含む分析パッケージ
- 入力上限、無視と除外の区別、不変性
- 日英メッセージのキー一致と不適切な由来表現の不在
- HTMLのスクリプト順序、タブARIA、外部スクリプト、CSP

GitHub Actionsはpushとpull requestでNode.js 22の`npm test`を実行します。

## 10. 制約

このツールは対応表に基づく計算だけを行います。同値の語に意味的関係があるか、歴史的解釈が正しいか、予言・真正性・暗号安全性の根拠になるかは判定しません。
